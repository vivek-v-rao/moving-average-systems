# Interpreting `--deflate` results

This document walks through a real `xma_signal` search and explains what the ordinary backtest statistics and the multiple-testing diagnostics mean together.

The example command is:

```bash
python xma_signal.py [SPY IEF TLT] 1 2:200 --trade SPY --read-prices-file prices.csv --terse --time --best --deflate
```

The run searches moving-average signals generated by SPY, IEF, and TLT, but every candidate strategy trades SPY. `MA1` is fixed at 1 day and `MA2` ranges from 2 through 200 days.

The important point is that this is an **in-sample search**. The program first finds the candidate with the highest historical Sharpe ratio and then uses `--deflate` to ask how much confidence should be placed in that winner after accounting for the fact that many correlated candidates were examined.

## 1. How many strategies were searched?

There are three signal assets and 199 values of `MA2`:

```text
3 signal assets x 1 MA1 value x 199 MA2 values x 1 threshold = 597 strategies
```

That is the `Raw = 597` value in the deflation table.

The strategies are not independent. For example, an IEF `MA(1)/MA(20)` signal and an IEF `MA(1)/MA(21)` signal will usually have very similar historical states and returns. IEF and TLT signals can also be related because the underlying assets are both interest-rate-sensitive bond ETFs.

This dependence is why `--deflate` reports several effective numbers of trials rather than treating all 597 candidates as independent experiments.

## 2. The common backtest window

The summary reports:

```text
2003-05-15 to 2026-09-24
5,878 trading days
23.33 years
```

The default common-window logic evaluates the candidates over a comparable history after allowing enough observations for the longest requested moving average and the normal one-session execution delay.

The deflation table also reports `Obs = 5878`, the number of common return observations used to compare the candidate strategy return streams.

Using a common window matters because otherwise a high Sharpe from a short or unusually favorable subperiod could be compared directly with a Sharpe estimated over a much longer history.

## 3. Interpreting the selected strategy

The best in-sample candidate was:

```text
Signal   MA1   MA2   Trade   Return    Vol    Sharpe   Beta   Alpha
IEF        1     7   SPY     12.77%  14.07%    0.71    0.58   4.51%
```

With `MA1 = 1`, the first moving average is simply the current IEF adjusted close. The rule is therefore approximately:

```text
IEF adjusted close > IEF 7-day moving average -> SPY up state
IEF adjusted close <= IEF 7-day moving average -> SPY down state
```

Signals observed at the close affect the position beginning with the next trading session.

Because this command does not specify `--down-pos` or `--down-symbol`, the default down-state SPY position is zero and the residual allocation is cash. Because it does not specify `--cash-rate`, the program's default annual cash rate is used.

### Return and volatility

`Return = 12.77%` is the strategy CAGR over the common backtest window. `Vol = 14.07%` is annualized daily-return volatility.

These are historical, in-sample quantities. They are not forecasts.

### Sharpe = 0.714

The strategy's annualized Sharpe ratio is approximately 0.714 relative to the configured cash rate.

This is the statistic used by `--best` to choose the winning candidate. Because the candidate was selected from 597 alternatives, 0.714 should not be interpreted in the same way as a Sharpe of 0.714 from a strategy specified before examining the data.

That selection effect is the reason for the remaining diagnostics.

### Beta = 0.58 and alpha = 4.51%

The strategy had a historical beta of approximately 0.58 relative to buy-and-hold SPY. Its annualized alpha relative to SPY buy-and-hold was approximately 4.51% under the program's regression-style calculation.

The lower beta is unsurprising because the strategy was invested in SPY only part of the time.

### Average position and turnover

The selected strategy reports:

```text
Changes/year = 55.48
AvgPos        = 0.54
CashWt        = 0.46
```

Historically it held roughly 54% SPY on average and 46% cash on average. It changed position about 55 times per year, or roughly once per week on average.

This matters because the example uses zero transaction cost:

```text
cost 0.000%/unit turnover
```

A rule trading this frequently should also be examined with realistic transaction-cost and implementation assumptions. For example:

```bash
python xma_signal.py [SPY IEF TLT] 1 2:200 --trade SPY --read-prices-file prices.csv --cost 0.0005 --terse --best --deflate
```

would apply a 0.05% cost per unit of absolute position turnover. The appropriate cost assumption depends on the intended implementation.

### MA Dev = -1.12%

At the end of the supplied data, IEF's `MA1 / MA2 - 1` for the selected 1/7 rule was approximately -1.12%.

With a zero threshold, this means the contemporaneous signal was in its down state at the final price observation. Remember that the backtest applies signals with the program's execution timing rather than assuming a trade at the same close used to calculate the signal.

## 4. Mean strategy correlation: 0.665

The deflation analysis reports:

```text
MeanCorr = 0.665
```

This is the mean pairwise correlation among the daily return streams of the 597 tested strategies over their common observations.

A value of 0.665 shows substantial redundancy. The experiment did not contain 597 unrelated bets. Many candidate systems behaved similarly.

This fact is central to interpreting the effective-trial counts below.

## 5. Why are there three different effective numbers of trials?

The output reports:

```text
Raw       = 597
EffN-B    = 200.58
EffN-G    = 20.99
EffN-max  = 6.95
```

These numbers are intentionally different because they answer different questions. There is no single uniquely correct scalar measure of the dependence among hundreds of strategy return streams.

### EffN-B = 200.58

`EffN-B` uses the average-correlation approximation:

```text
EffN-B = rho + (1 - rho) * M
```

where `rho` is mean pairwise return correlation and `M` is the raw number of candidates.

It is the effective-trial count used by the program's standard Deflated Sharpe search hurdle. With mean correlation around 0.665, the 597 raw strategies behave like roughly 201 independent trials under this particular approximation.

This measure uses only average correlation, so it does not capture the full eigenvalue structure of the strategy correlation matrix.

### EffN-G = 20.99

`EffN-G` is the Galwey eigenvalue effective number of tests. It uses the entire eigenvalue spectrum of the 597 x 597 strategy-return correlation matrix.

The value of roughly 21 says that the correlation matrix has far lower effective dimensionality than its raw dimension of 597.

This is a useful measure of redundancy, but it is not specifically designed around the behavior of the single maximum Sharpe.

### EffN-max = 6.95

`EffN-max` is targeted at maximum selection. The program simulates correlated Gaussian statistics using the estimated full strategy correlation matrix and asks how many **independent** Gaussian trials would have the same expected maximum.

For this run, the maximum-selection behavior is similar to only about seven independent Gaussian trials.

That is much smaller than both 597 and `EffN-B`. It reflects the extreme similarity of the candidates from the perspective of their maximum statistic.

The three effective counts should therefore be viewed as complementary sensitivity measures, not as competing estimates from which one must choose the "correct" answer.

## 6. The cross-sectional Sharpe distribution

The table reports:

```text
MeanSR = 0.460
SR sd  = 0.102
```

Across all 597 tested strategies, the average in-sample Sharpe was approximately 0.460, and the cross-sectional standard deviation of the Sharpes was approximately 0.102.

This is important context. The winning Sharpe of 0.714 did not emerge from a family centered around zero. The whole tested family performed fairly well in-sample.

It also means that there are two distinct questions:

1. **Does the winner look better than a zero-Sharpe benchmark after allowing for the search?**
2. **Is the winner genuinely better than the other members of this already-good strategy family?**

DSR and the empirical-Bayes estimate address these questions differently.

## 7. SR0 = 0.281

The program reports:

```text
SR0 = 0.281
```

`SR0` is the program's standard DSR-style search hurdle. It combines the cross-sectional Sharpe dispersion with the expected maximum associated with `EffN-B`.

The idea is that even when the underlying candidates do not differ meaningfully, selecting the maximum from many noisy Sharpe estimates can produce an apparently attractive winner. `SR0` estimates a Sharpe level attributable to that search mechanism under the model used by the program.

The winning Sharpe of 0.714 is substantially above the 0.281 hurdle.

## 8. Haircut = 0.433

The output gives:

```text
Haircut = BestSR - SR0
        = 0.714 - 0.281
        = 0.433
```

Despite the column name, **0.433 should not be treated as a forecast of the strategy's future Sharpe**.

It is simply the amount by which the observed Sharpe exceeds the DSR search hurdle. It is useful as a selection-bias diagnostic, not as an adjusted expected return.

## 9. PSR

For the best candidate:

```text
PSR = 1.000
```

PSR is the program's probabilistic Sharpe diagnostic relative to a Sharpe benchmark of zero. Its sampling calculation uses the number of return observations plus the candidate's skewness and kurtosis.

With more than 5,800 daily observations, a Sharpe around 0.71 is far enough from zero that the displayed probability rounds to 1.000.

This should not be read as a literal 100% probability that the strategy will make money in the future. It is a sampling-model diagnostic about the historical Sharpe relative to the specified benchmark.

## 10. DSR = 0.982

For the winner:

```text
DSR = 0.982
```

DSR uses the same Sharpe sampling framework as PSR but compares the candidate with the search-adjusted hurdle `SR0 = 0.281` rather than with zero.

A DSR of 0.982 means that, under the program's sampling approximation, the observed Sharpe is strongly above the multiple-testing hurdle generated by this particular search.

This is encouraging evidence that the result is not explained solely by selecting the maximum of many candidates. It is still an in-sample diagnostic and is not a prediction of future Sharpe.

## 11. Max-p = 0.0068

The winning strategy reports:

```text
Max-p = 0.0068
```

The program simulates the maximum of correlated Gaussian test statistics using the estimated 597-strategy correlation matrix. `Max-p` is the fraction of simulated family maxima at least as extreme as the candidate's Sharpe test statistic, with a small finite-simulation correction.

A value of 0.0068 corresponds to roughly 0.68% under that model. In other words, the observed winner is unusual relative to a zero-Sharpe null even after accounting for the correlation-aware maximum over the tested family.

`Max-p` is model-based. In particular, the maximum simulation is Gaussian and only includes the strategies present in this run.

## 12. EB SR = 0.460: why does the winner shrink so much?

Perhaps the most interesting result is:

```text
Observed best Sharpe = 0.714
EB SR                = 0.460
Family mean Sharpe   = 0.460
```

The top five displayed candidates all have `EB SR = 0.460`.

This is not a bug. The empirical-Bayes calculation asks a different question from DSR.

It estimates how much **true cross-strategy Sharpe dispersion** remains after subtracting an estimate of Sharpe sampling noise, allowing that estimation errors are correlated across strategies. In this run, the estimated between-strategy variance is effectively zero after that adjustment. The resulting shrinkage weights are therefore near zero, so the individual Sharpes collapse toward the family mean of approximately 0.460.

A useful interpretation is:

> The data provide substantial evidence that this tested strategy family performed better than a zero-Sharpe benchmark in-sample, but much weaker evidence that the particular 1/7 IEF winner has a genuinely higher expected Sharpe than the other members of the family.

That reconciles the apparently different messages from `DSR = 0.982` and `EB SR = 0.460`.

The empirical-Bayes estimate is still based on the same historical sample. The family mean itself can be optimistic if the researcher chose SPY, IEF, TLT, the MA family, the sample dates, or other design choices after examining related data.

## 13. The top candidates are clustered rather than isolated

The highest-Sharpe candidates are:

```text
IEF  MA(1)/MA(7)    Sharpe 0.714
IEF  MA(1)/MA(8)    Sharpe 0.706
TLT  MA(1)/MA(17)   Sharpe 0.689
IEF  MA(1)/MA(6)    Sharpe 0.676
TLT  MA(1)/MA(18)   Sharpe 0.670
```

There are two encouraging qualitative features:

- the IEF winner has neighboring MA lengths 6 and 8 among the leading candidates; and
- TLT has neighboring lengths 17 and 18 among the leaders.

This is more reassuring than a single isolated parameter combination surrounded by poor results. It suggests broad local performance regions rather than one uniquely lucky integer length.

It does **not** establish out-of-sample robustness. Neighboring rules are highly correlated, which is precisely why the effective-trial counts are much smaller than the raw count.

## 14. Redundancy decomposition

The report separates redundancy in moving-average choice from redundancy in signal-asset choice.

### MA variants within each signal asset

```text
SPY: raw 199, effective 10.47
IEF: raw 199, effective  7.03
TLT: raw 199, effective  7.52
```

Under the Galwey measure, the 199 moving-average lengths for a given signal asset behave like only about 7 to 10 effective dimensions.

This confirms the intuition that adjacent moving-average lengths are strongly redundant.

### Signal assets at fixed MA length

```text
raw signal assets = 3
mean effective    = 2.31
range             = 2.24 to 2.36
```

Holding the MA specification fixed, SPY, IEF, and TLT behave like roughly 2.3 effective signal assets rather than three fully independent signals.

This says that the redundancy from changing MA length is much stronger than the redundancy from changing among the three signal assets in this run.

## 15. What is the overall message of this run?

A reasonable summary is:

1. **The raw search was large:** 597 strategies were evaluated.
2. **The search was highly redundant:** mean strategy-return correlation was 0.665, and the effective-trial measures were far below 597.
3. **The historical winner was strong:** IEF `MA(1)/MA(7)` produced an in-sample Sharpe of about 0.714 while trading SPY.
4. **The winner clears the program's search-adjusted significance hurdles:** DSR was 0.982 and correlation-aware `Max-p` was about 0.0068.
5. **The exact winner is much less certain:** the empirical-Bayes calculation shrinks its Sharpe all the way to the family mean of about 0.460, suggesting little estimated cross-strategy advantage after allowing for sampling noise.
6. **The best results form small clusters:** IEF lengths 6-8 and TLT lengths 17-18 all appear near the top, which is preferable to one isolated parameter spike.
7. **Implementation assumptions still matter:** the winning rule changes position about 55 times per year, while this run assumes zero transaction cost.
8. **Nothing here replaces out-of-sample testing:** all diagnostics are calculated from the same history used to search the strategy family.

The strongest claim supported by this run is therefore not "IEF 1/7 has a true Sharpe of 0.714." A more cautious interpretation is:

> This historical sample contains evidence that short-horizon bond-ETF moving-average signals were useful for timing SPY within the tested family, but the data provide much less evidence that the single best integer parameter choice is superior to nearby or related alternatives.

## 16. Useful follow-up checks

### Add transaction costs

Because the selected system trades frequently, rerun with plausible cost assumptions:

```bash
python xma_signal.py [SPY IEF TLT] 1 2:200 --trade SPY --read-prices-file prices.csv --cost 0.0005 --terse --best --deflate
```

and perhaps compare several cost rates.

### Increase Monte Carlo simulations

`EffN-max` and `Max-p` use simulation. For a final reported result, a larger simulation count reduces Monte Carlo noise:

```bash
python xma_signal.py [SPY IEF TLT] 1 2:200 --trade SPY --read-prices-file prices.csv --terse --best --deflate --deflate-sims 100000 --deflate-seed 12345
```

### Examine different historical windows

A robust signal should not owe all of its apparent value to one particular starting or ending date. Use `--trade-date-min` and `--trade-date-max` to study subperiods without changing the basic strategy definition.

### Use genuinely untouched data

The cleanest validation is to choose the rule or rule family using one period and evaluate it on data that played no role in the selection process.

Rolling or expanding-window evaluation can also help determine whether a relationship persists through time.

## 17. Important limitations of the statistical diagnostics

The `--deflate` output is designed to make a large in-sample search more transparent, but it cannot account for every source of research overfitting.

In particular:

- it only knows about strategies included in the current run;
- it cannot know how many assets, indicators, date ranges, thresholds, or strategy ideas were tried previously and discarded;
- the PSR/DSR sampling calculation uses skewness and kurtosis but does not explicitly apply a HAC or other serial-correlation correction to Sharpe uncertainty;
- `Max-p` uses a Gaussian correlated-max approximation;
- the empirical strategy correlation matrix is itself estimated from historical data;
- the empirical-Bayes family mean is still an in-sample estimate; and
- market relationships can change after the sample ends.

For these reasons, `--deflate` should be viewed as an **in-sample research diagnostic**, not as a substitute for independent validation.
